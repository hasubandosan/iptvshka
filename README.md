# IPTV Manager

Личный менеджер IPTV-плейлиста на GitHub. Вы пишете список каналов, которые хотите видеть, а система сама находит для них рабочие потоки и раз в сутки обновляет готовый `playlist.m3u`. Сервер не нужен: всё работает бесплатно на GitHub Actions и GitHub Pages.

## Что это умеет

- **Собирает плейлист только из ваших каналов.** Никакой агрегации тысяч лишних каналов.
- **Ищет потоки сам.** Для канала без ссылки скрипт просматривает плейлисты-источники, проверяет найденные потоки и берёт первый рабочий.
- **Принимает ваши жёсткие ссылки.** Можно указать основную ссылку и запасные: берётся первая живая.
- **Проверяет доступность.** Асинхронная проверка с таймаутом 4 секунды, около 50 потоков одновременно.
- **Не теряет каналы.** Если свежий поток не нашёлся, остаётся ссылка из прошлого плейлиста.
- **Сохраняет атрибуты.** `tvg-id`, `tvg-name`, `tvg-logo`, `group-title` и служебные строки (`#EXTVLCOPT` и т. п.) переносятся как есть. Любой атрибут можно переопределить вручную.
- **Обновляется автоматически.** Раз в сутки, по кнопке и после каждой правки списка каналов.
- **Имеет веб-редактор.** Тёмный интерфейс для правки списка с телефона или компьютера, с сохранением прямо в репозиторий.

## Как это устроено

```
 Плейлисты-источники (sources)          Ваш список (channels.json)
            │                                      │
            └──────────────┬───────────────────────┘
                           ▼
              update_playlist.py  (GitHub Actions, раз в сутки)
                           │
             поиск → проверка потоков → сборка
                           ▼
                     playlist.m3u  ──►  ваш IPTV-плеер (по raw-ссылке)

 index.html (редактор) ──► правит channels.json ──► запускает обновление
```

## Файлы

| Файл | Назначение |
|---|---|
| `channels.json` | **Главный файл.** Список нужных вам каналов и их порядок. |
| `config.json` | Настройки: источники, проверка потоков, EPG. |
| `update_playlist.py` | Скрипт, который собирает плейлист. |
| `playlist.m3u` | Готовый плейлист для всех. Создаётся автоматически, руками не правится. |
| `playlist_adult.m3u` | Отдельный плейлист для взрослых (группа `Adults`). Тоже создаётся автоматически. |
| `.github/workflows/update.yml` | Расписание и запуск скрипта в GitHub Actions. |
| `requirements.txt` | Зависимости Python (`aiohttp`). |
| `index.html` | Веб-редактор `channels.json`. |

## Быстрый старт

1. Создайте репозиторий на GitHub и загрузите в него все файлы, сохранив структуру папок. Папку `.github/workflows/` проще создать так: Add file → Create new file → в имени файла введите `.github/workflows/update.yml`.
2. Откройте Settings → Actions → General → Workflow permissions и включите **Read and write permissions**.
3. Отредактируйте `channels.json` под себя (см. ниже).
4. Откройте вкладку Actions → Update IPTV playlist → **Run workflow**.
5. Когда запуск завершится, в корне появится `playlist.m3u`. Ссылка для плеера:
   `https://raw.githubusercontent.com/ЛОГИН/РЕПОЗИТОРИЙ/main/playlist.m3u`

## Список каналов (`channels.json`)

Каждая запись в массиве `channels` это один канал. Порядок записей равен порядку в плейлисте.

**Канал, который надо найти в источниках:**
```json
{ "name": "Муз ТВ", "group": "Музыка" }
```

**Канал с вашей жёсткой ссылкой** (первая ссылка основная, остальные запасные):
```json
{
  "name": "Мой канал",
  "url": ["http://example.com/main.m3u8", "http://example.com/backup.m3u8"],
  "logo": "https://example.com/logo.png",
  "group": "Свои"
}
```

Если в записи есть `url`, канал добавляется как жёсткая ссылка. Если `url` нет, он ищется в источниках.

### Поля записи

| Поле | Обязательное | Описание |
|---|---|---|
| `name` | да | Название, под которым канал попадёт в плейлист. |
| `url` | нет | Ссылка на поток (строка или список). Если задана, поиск не выполняется. |
| `match` | нет | Варианты названия для поиска (строка или список). По умолчанию ищется точное `name`. |
| `group` | нет | Свой `group-title`. Иначе берётся из источника. |
| `logo` | нет | Свой `tvg-logo`. Иначе берётся из источника. |
| `tvg_id` | нет | Свой `tvg-id` (для программы передач). |
| `tvg_name` | нет | Свой `tvg-name`. |
| `extra` | нет | Список дополнительных строк, например `["#EXTVLCOPT:http-user-agent=VLC"]`. |

### Как сопоставляются названия

Регистр, пробелы, дефисы, знаки и буква «ё» не учитываются, поэтому «Муз ТВ», «МУЗ-ТВ» и «Муз-ТВ HD» считаются одним каналом.

- `"match": "ТНТ"` найдёт любое название, где встречается «ТНТ», включая «ТНТ4» и «ТНТ Music».
- `"match": "=ТНТ"` найдёт только точное «ТНТ». Пометки HD, SD, FHD, UHD и 4K при точном сравнении игнорируются.
- Можно перечислить несколько вариантов: `"match": ["=Рыбалка и охота", "=Охота и рыбалка"]`.

Среди найденных вариантов сначала проверяются точные совпадения, затем остальные, в порядке источников. Проверяется не больше `max_candidates` вариантов.

## Настройки (`config.json`)

| Поле | По умолчанию | Описание |
|---|---|---|
| `sources` | (примеры) | Ссылки на `.m3u` / `.m3u8`, где скрипт ищет каналы. Выше в списке значит приоритетнее. |
| `channels_file` | `channels.json` | Файл со списком каналов. |
| `output` | `playlist.m3u` | Имя итогового файла. |
| `epg_url` | пусто | Ссылка на программу передач. Если пусто, берётся из первого источника, где она есть. |
| `check.enabled` | `true` | Выключите, чтобы не проверять потоки и брать первый найденный. |
| `check.timeout` | `4` | Таймаут проверки одного потока, секунды. |
| `check.concurrency` | `50` | Сколько потоков проверять одновременно. |
| `check.retries` | `1` | Повторных попыток при неудаче. |
| `check.max_candidates` | `8` | Сколько вариантов одного канала проверять. |
| `check.strict_hls` | `true` | Для `.m3u8` требовать, чтобы ответ начинался с `#EXTM3U`. |
| `check.keep_non_http` | `true` | Оставлять ссылки `rtmp://`, `udp://` и т. п., их нельзя проверить. |
| `check.user_agent` | `Mozilla/5.0 ...` | User-Agent при проверке. |

Файл в формате JSON не допускает комментариев и лишних запятых в конце списков.

## Веб-редактор (`index.html`)

Редактор правит `channels.json` без ручной работы с JSON.

- Добавление, редактирование и удаление каналов.
- Изменение порядка кнопками ▲▼, а на компьютере ещё и перетаскиванием.
- Поиск по названию и группе, фильтр по группам.
- Вкладка «Источники»: добавление, удаление, смена приоритета и быстрая проверка ссылок на плейлисты (правит `config.json`).
- Загрузка и сохранение `channels.json` и `config.json` напрямую в GitHub.
- Открытие файла с устройства и скачивание JSON.

**Подключение:**
1. Опубликуйте страницу: Settings → Pages → Deploy from a branch → `main` → `/ (root)`. Адрес будет `https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/`. Либо откройте `index.html` как обычный файл.
2. Создайте fine-grained токен: GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens. В Repository access выберите только нужный репозиторий, в Permissions нажмите **Add permissions**, выберите **Contents** и поставьте **Read and write**.
3. В редакторе нажмите «GitHub», введите `логин/репозиторий` и токен, затем «Запомнить».
4. Нажмите «Загрузить с GitHub» (загрузятся и каналы, и источники), внесите правки, нажмите «Сохранить». После сохранения запустится обновление плейлиста.

Токен хранится только в браузере. Открывайте редактор лишь на своих устройствах.

## Расписание и запуск

- **По расписанию:** каждый день в 03:00 UTC (06:00 по Москве). Время меняется в строке `cron` файла `update.yml`.
- **Вручную:** Actions → Update IPTV playlist → Run workflow.
- **Автоматически:** после изменения `channels.json`, `config.json` или `update_playlist.py`.

Если в репозитории нет активности 60 дней, GitHub может отключить запуск по расписанию. Обычно этого не происходит, пока бот коммитит обновлённый плейлист. Если плейлист долго не меняется, включите workflow вручную.

## Как читать лог обновления

Во вкладке Actions откройте последний запуск. Для каждого канала выводится статус:

| Статус | Что значит и что делать |
|---|---|
| `OK` | Рабочий поток найден. |
| `свежий поток не найден, оставлена ссылка из прошлого плейлиста` | Сейчас потоков нет, используется старая ссылка. Проверьте источники. |
| `НЕ НАЙДЕН в источниках` | Канал не встретился ни в одном источнике. Проверьте название, добавьте `match` или новый источник. |
| `НАЙДЕН, но все потоки не отвечают` | Варианты есть, но все мертвы или недоступны. Добавьте другой источник или свою ссылку. |
| `ваша ссылка не отвечает (оставлена как есть)` | Ваша жёсткая ссылка не прошла проверку. Проверьте её. |

Если итоговый плейлист получился пустым, `playlist.m3u` не перезаписывается, а запуск завершается ошибкой.

## Частые вопросы

**Канал есть в источнике, но скрипт его не находит.**
Название записано иначе. Найдите его в источнике и укажите в `match`, при необходимости несколько вариантов.

**В браузере или плеере поток работает, а скрипт считает его мёртвым.**
Проверка идёт с серверов GitHub, которые расположены за рубежом. Потоки с ограничением по региону или по User-Agent могут так не проходить. Используйте жёсткую ссылку (она всё равно попадает в плейлист), задайте `extra` с нужным заголовком или отключите проверку в `config.json`.

**Ссылки со временными токенами быстро протухают.**
Скрипт обновляется раз в сутки. Для таких потоков он подходит плохо.

**Добавить приватный плейлист провайдера.**
Не публикуйте ссылку с логином или паролем в открытом репозитории. Сделайте репозиторий приватным.

**Изменить время обновления.**
Отредактируйте `cron` в `.github/workflows/update.yml`. Формат: `минуты часы * * *`, время UTC.

**Запустить скрипт у себя на компьютере.**
`pip install -r requirements.txt`, затем `python update_playlist.py`. Файл `playlist.m3u` появится рядом со скриптом.

## Ограничения

- Проверка показывает, что сервер отвечает и отдаёт данные, но не гарантирует качество картинки.
- Ссылки `rtmp://`, `udp://` и подобные проверить нельзя, они остаются в плейлисте без проверки.
- Скрипт не создаёт потоки, он только находит и проверяет ссылки. Используйте только плейлисты и потоки, которые вы имеете право смотреть: открытое вещание или ваша собственная подписка.

## Каналы, заблокированные по региону (заставка «недоступно в вашем регионе»)

Проверка потоков работает с серверов GitHub и видит только «валидный HLS». Заставка Wink/OTT Club — тоже валидный HLS, поэтому такая ссылка считается рабочей.
Чтобы этого не происходило, в `config.json` есть чёрный список `blocked`: любой поток, чей URL содержит одну из этих подстрок, пропускается при поиске (и не берётся из старого плейлиста).

```json
"blocked": ["zabava-htlive.cdn.ngenix.net", "ott.watch", "ottclub", "wink.ru"]
```

Для одного канала можно добавить `exclude` в `channels.json`:

```json
{ "name": "Рен ТВ", "match": ["Рен ТВ"], "exclude": ["ngenix"] }
```

Если для канала остались только заблокированные варианты, он не попадёт в плейлист, а в логе будет «НЕ НАЙДЕН». Тогда добавьте рабочий источник в `sources` или задайте жёсткую `url`.
Чтобы вернуть хост — просто удалите его из `blocked`.

## Сортировка каналов

В `config.json` задаётся режим `sort`:

| Значение | Что делает |
|---|---|
| `manual` | По умолчанию. Порядок как в `channels.json`. |
| `name` | По алфавиту, по названию канала. |
| `group` | По группам; внутри группы порядок как в `channels.json`. |
| `group_name` | По группам, а внутри группы по алфавиту. |

Порядок самих групп задаёт `group_order`. Группы, которых нет в списке, идут после него по алфавиту, каналы без группы в самом конце.

```json
"sort": "group_name",
"group_order": ["Развлекательные", "Музыка", "Познавательные", "Хобби"]
```

Сортировка применяется к каждому плейлисту отдельно (обычному и для взрослых).

## Отдельный плейлист для взрослых

В `config.json` есть блок `adult`:

```json
"adult": { "enabled": true, "groups": ["Adults"], "output": "playlist_adult.m3u" }
```

- Канал попадает в `playlist_adult.m3u` и **не попадает** в `playlist.m3u`, если его группа (`group`) входит в `adult.groups`.
- Отдельного канала можно пометить вручную: `"adult": true` в записи `channels.json`. Значение `false` оставляет канал в обычном плейлисте, даже если группа взрослая.
- Ссылка для плеера: `https://raw.githubusercontent.com/ЛОГИН/РЕПОЗИТОРИЙ/main/playlist_adult.m3u`.
- `"enabled": false` возвращает старое поведение: всё в одном `playlist.m3u`.

## Группы в веб-редакторе

Каналы в редакторе показываются секциями по группам (порядок групп = порядок первого появления в `channels.json`). Клик по заголовку группы сворачивает и разворачивает её.

- **Перетаскивание мышью:** на карточку (выше или ниже её середины) вставляет канал перед или после неё. Если карточка из другой группы, канал переходит в эту группу. Если бросить на заголовок группы, канал встанет в её начало (можно и в свёрнутую).
- **Кнопки ▲ ▼** (для телефона): шаг внутри группы; на краю группы канал переходит в соседнюю.
- После любого перемещения или правки каналы одной группы идут в `channels.json` подряд, так что при `"sort": "manual"` порядок в плейлисте совпадает с тем, что вы видите на экране.
- При включённом поиске или фильтре по группе перестановка отключена.

## Выбор лучшей ссылки по скорости

Если канал найден в нескольких источниках, скрипт не берёт первый попавшийся, а сравнивает кандидатов. Блок `speed` в `config.json`:

```json
"speed": { "enabled": true, "rank_by": "speed", "min_ratio": 1.3, "tolerance": 0.15,
           "max_probe": 4, "segments": 2, "timeout": 10, "concurrency": 3, "max_variant_mbps": 8 }
```

Как это работает:
1. Из кандидатов остаются только живые (проверка как раньше).
2. Для первых `max_probe` живых HLS-потоков скачиваются `segments` последних сегментов, и считается: скорость загрузки (Мбит/с), запас `ratio` (секунд видео за секунду загрузки) и реальный битрейт. В мастер-плейлисте берётся лучший вариант качества не выше `max_variant_mbps`.
3. Потоки с `ratio` ниже `min_ratio` считаются «медленными» (будут буферизировать) и выбираются, только если больше ничего нет.
4. Среди остальных побеждает лучший по `rank_by`: `speed` (максимальная скорость) или `quality` (максимальный битрейт, то есть картинка получше).
5. Результаты в пределах `tolerance` (15%) от лучшего считаются равными, и побеждает тот, кто выше по приоритету (точное название, порядок источников). Так плейлист не «прыгает» между ссылками из-за шума замера.
6. Потоки, которые нельзя замерить (не HLS, например прямой `.ts`), ставятся после «плавных» и перед «медленными».

В логе Actions для каждого канала видно скорости всех кандидатов, например:
`[OK] Рен ТВ — 12.4 Мбит/с, запас ×6.1, поток ~2.0 Мбит/с | выбран host-a из: host-a 12.4; host-b 3.1; host-c н/д`

**Важно.** Скорость меряется с серверов GitHub, а не из Молдовы. Замер показывает, какой сервер быстрее и стабильнее отдаёт поток, но не учитывает ваш провайдер и маршрут. Блокировки по региону он тоже не видит, для этого есть `blocked`.
Замеры увеличивают время запуска (десятки каналов, по несколько потоков на каждый, обычно несколько минут) и трафик раннера. Отключить: `"enabled": false` (тогда берётся первый живой кандидат). Жёстким ссылкам (`url`) это не применяется: берётся первая живая из вашего списка.
